# تقرير المرحلة 10 — الاختبار الشامل والأداء والاستقرار

## ما تم إنجازه
1. **اختبار رحلة المستخدم كاملة على المحرك الحقيقي** (عملية uvicorn منفصلة، لا عميل اختبار داخلي):
   الإعدادات ← قاعدة في المكتبة ← اعتماد تقرير التعلم ← استيراد بيانات CSV ← استراتيجية ← اختبار تاريخي يجتاز البوابة ← اعتماد ← رفع شارت ← **BUY بالخطوات الـ14** ← تسجيل النتيجة ← الإحصاءات ← نسخة احتياطية مشفرة ← **حذف كل البيانات** ← **استعادة** (الاستراتيجية معتمدة، الإشارة، الإحصاءات، الإعدادات — كلها عادت) ← إيقاف نظيف بإشارة SIGTERM.
2. **الاستقرار والاستعادة**:
   - **قطع مفاجئ أثناء الكتابة** (قتل العملية بـ SIGKILL بعد 300+ عملية): لا فقد لأي بيانات أُكدت كتابتها، وقاعدة البيانات سليمة.
   - **قاعدة بيانات تالفة عند التشغيل**: تُحفظ كما هي باسم `.corrupt-<الوقت>` (لا تُستبدل أبداً)، يبدأ المحرك بقاعدة جديدة، وتظهر **رسالة واضحة في اللوحة** تقترح استعادة آخر نسخة احتياطية.
   - **إيقاف نظيف**: إيقاف قراءة الشاشة وانتظار مهمة الفيديو الجارية عند إغلاق المحرك.
3. **مراجعة أمنية**:
   - فحص آلي (bandit) على كل كود المحرك: **0 مشاكل**؛ 10 استثناءات موثقة داخل الكود بسببها (أسماء أعمدة من قوائم مسموحة، أوامر FFmpeg ثابتة بلا shell) — ومضاف إلى CI.
   - **ثغرة أُغلقت**: صفحات التوثيق `/docs` و`/openapi.json` كانت تُعرض **بدون توكن** لأي برنامج محلي ⇒ عُطلت.
   - اختبار أن **كل مسار** (عدا `/health`) يتطلب التوكن؛ محاولات حقن SQL وFTS عبر البحث والتصفية والتعديل لا أثر لها؛ رفض المدخلات الضخمة والمشوهة.
   - `assert` في كود الإنتاج استُبدل بفحص صريح (يُحذف assert في Python المحسّن).
4. **الأداء** (`python -m bench.benchmark`) — قياس ثم تحسين:

| العملية | قبل | بعد | السبب |
|---|---|---|---|
| قراءة شارت 1920×1080 بدون OCR | 393 ms | **111 ms** (3.5×) | نسخ كامل للصورة كان يتكرر لكل شمعة |
| معالجة إطار كاملة (قراءة+OCR ← تحليل ← قرار) | 725 ms | **471 ms** | نفس السبب |
| اختبار تاريخي 20 000 شمعة (دعم/مقاومة) | 7 262 ms | **322 ms** (22×) — **نفس الـ1760 صفقة** | بحث ثنائي للقمم المؤكدة، ذاكرة مؤقتة للمستويات، تقييم الشروط الرخيصة أولاً، متوسط تراكمي |
| أقصى ذاكرة أثناء القراءة المتكررة | 671 MB | **225 MB** | إزالة النسخ غير الضرورية |
