# تقرير المرحلة 1 — الهيكل، بيئة التطوير، واجهة Windows، قاعدة البيانات المحلية

## ما تم إنجازه
1. **التصميم**: المخطط المعماري، هيكل الملفات، مخطط قاعدة البيانات الكامل لكل المراحل، تصميم الواجهة، خطة الاختبارات (`docs/`).
2. **المحرك المحلي (Python/FastAPI)** يعمل فعلياً على `127.0.0.1:8765`:
   - قاعدة بيانات SQLite بـ 15 جدولاً وترحيلات مرقمة ووضع WAL.
   - إعدادات قابلة للتعديل مع التحقق، بالقيم الافتراضية المطلوبة (شمعة 30ث، مدة 60–180ث، يدوي فقط، لا إشارة دون شروط، 3 عوامل متوافقة على الأقل، منع التكرار 30ث، 15 عاملاً قابلاً للتفعيل/التعطيل).
   - التحكم بجلسات التحليل + **إيقاف فوري** يلغي إذن الشاشة والتحليل المستمر.
   - مكتبة المعرفة: ملاحظات، ملفات (عنونة بالمحتوى ومنع التكرار)، روابط، تصنيف ووسوم، بحث FTS5 يدعم العربية، ربط المعلومات، مصدر وتاريخ كل معلومة، **بوابة الموافقة** (لا يرى المحرك إلا المعتمد).
   - سجل الإشارات بقواعد إلزامية، ويوميات نتائج تفصل محاكاة/تجريبي/حقيقي.
   - نسخ احتياطي مشفر (scrypt + AES-256-GCM مقطعي)، استعادة آمنة، حذف كل البيانات.
   - سجل تدقيق/تعلم لكل عملية.
   - أمان: ربط محلي فقط، توكن لكل تشغيل، صلاحيات ملفات للمالك فقط، لا نقاط نهاية للتداول.
3. **تطبيق Flutter** (Windows أولاً، والمشروع مهيأ لـ Android وiOS):
   - لوحة عائمة بلا إطار، فوق التطبيقات، قابلة للسحب وتغيير الحجم والشفافية، تتذكر موضعها.
   - BUY أخضر، SELL أحمر، WAIT، حالة التحليل، الثقة (مع وسم "غير معايرة")، المدة، الإطار الزمني، بدء/إيقاف/إيقاف فوري، المكتبة، التدريب، السجل، الإعدادات.
   - شاشات المكتبة والسجل والإعدادات تعمل بالكامل مع المحرك؛ شاشة التدريب تعرض الحالة الحقيقية للمكونات.
   - العربية (RTL) والإنجليزية، داكن/فاتح/النظام، تخطيط متكيف للشاشات العريضة.
   - تشغيل المحرك تلقائياً من `engine\uata-engine.exe` المجمّع.
4. **التغليف و CI**: سكربت بناء Windows (Flutter + PyInstaller)، وسير عمل GitHub Actions يشغّل كل الاختبارات ويبني نسخة Windows ويفحص المحرك المجمّع.

## الأخطاء التي عولجت
* `window_manager 0.7` يعتمد على بناء أصلي جديد يتطلب مكتبات GTK حتى لتشغيل الاختبارات ⇒ التثبيت على 0.5.x المستقر.
* اختبار الاتجاه RTL كان يقرأ `Directionality` الخاصة بـ MaterialApp ⇒ القراءة من سياق الزر نفسه.
* رسائل الخطأ كانت تُصفّ خلف رسالة النجاح السابقة فلا تظهر ⇒ إخفاء الرسالة الحالية قبل عرض الجديدة.
* إسناد بنمط Dart لحقول الكلاس غير مسموح ⇒ إعادة كتابة.
* `python -m pyinstaller` خاطئ ⇒ `PyInstaller`، وإضافة فحص رمز الخروج في سكربت PowerShell.

## ما لم يُنجز بعد (بصراحة)
* لا يوجد تحليل شارت ولا مؤشرات ولا إشارات بعد — لذلك تبقى التوصية WAIT دائماً مع شرح السبب.
* استخراج PDF/DOCX/XLSX والصور والفيديو: الملفات تُحفظ وتُفهرس وتُعلَّم "الاستخراج لاحقاً".
* الروابط تُحفظ دون جلب محتواها (لا اتصال بالإنترنت دون إذن).
* لم يُختبر التطبيق يدوياً على جهاز Windows حقيقي بعد؛ قائمة الاختبار اليدوي في `docs/TEST_PLAN.md`.
* Android/iOS: المشاريع مُنشأة لكن التكامل الأصلي (المحرك المضمّن، النافذة العائمة، الالتقاط) في المرحلة 2.
