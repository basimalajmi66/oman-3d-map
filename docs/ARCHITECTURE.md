# المخطط المعماري — Universal AI Trading Assistant

## 1. المبادئ الحاكمة
| المبدأ | كيف يُطبَّق |
|---|---|
| المستخدم صاحب القرار | لا توجد أي واجهة برمجية أو زر ينفذ صفقة. أزرار BUY/SELL تعرض التوصية وتفاصيلها فقط. `trading_mode` لا يقبل إلا `manual`. |
| محلي أولاً | كل البيانات في مجلد واحد على الجهاز (SQLite + مخزن ملفات). المحرك يستمع على `127.0.0.1` فقط. لا رفع سحابي. |
| لا معرفة دون موافقة | كل ما يُضاف يدخل بحالة `pending_review`. المحرك يبحث في `approved` فقط. تعديل محتوى عنصر معتمد يعيده للمراجعة. |
| الصدق قبل الشكل | حين لا يتوفر مكوّن، يقول النظام ذلك (`engine_available=false`, `unsupported_yet`) ويعرض WAIT بدل أي رقم مختلق. |
| لا قرار من مؤشر واحد | `min_confluence_factors ≥ 2` في الإعدادات، و`record_signal` يرفض BUY/SELL بعوامل أقل من الحد. |
| الثقة ليست احتمالاً | كل إشارة تحمل `confidence_calibrated`، ولا تكون 1 إلا بدليل معايرة خارج العينة. |

### لماذا محرك Python منفصل وواجهة Flutter؟
* **Python** هو المكان الطبيعي لـ OpenCV وOCR وFFmpeg وWhisper ونماذج ML المحلية وpandas للاختبار التاريخي.
* **Flutter** يعطي واجهة واحدة لـ Windows وAndroid وTablet وiOS.
* العقد بينهما (`EngineApi`) واجهة مجردة، فالواجهة لا تعرف هل المحرك عملية منفصلة أم مضمّن.

### تشغيل المحرك حسب النظام
| النظام | طريقة التشغيل | ملاحظات |
|---|---|---|
| Windows | `engine\uata-engine.exe` (PyInstaller) بجانب التطبيق، يشغّله `EngineLocator` تلقائياً | مُتحقق منه: الملف التنفيذي يُبنى ويعمل. |
| Android | Python مضمّن عبر **Chaquopy** يشغّل نفس الحزمة `uata` داخل التطبيق | المرحلة 2. يدعم numpy وOpenCV. النافذة العائمة عبر `SYSTEM_ALERT_WINDOW`، والالتقاط عبر `MediaProjection` بإذن صريح. |
| Tablet | نفس تطبيق Android بتخطيط متكيف (الشاشات العريضة تعرض قائمة + تفاصيل) | التخطيط المتكيف موجود منذ المرحلة 1. |
| iOS | تطبيق مرافق: تحليل صور/ملفات ومشاركة الشارت عبر Share Extension. المحرك إما مضمّن (Python-for-iOS) أو الاتصال بمحرك الكمبيوتر على الشبكة المحلية بعد اقتران صريح | iOS لا يسمح بنوافذ عائمة فوق التطبيقات ولا بالتقاط شاشة تطبيقات أخرى. |

## 3. الأمان
* المحرك يرتبط بـ `127.0.0.1` فقط.
* توكن عشوائي جديد في كل تشغيل يُكتب في `api_token` بصلاحيات المالك فقط (0600)، ولا تقبل أي نقطة نهاية (عدا `/health`) بدونه. يمنع ذلك صفحات المتصفح والبرامج الأخرى من التحكم بالمحرك (لا CORS).
* مجلد البيانات 0700، قاعدة البيانات 0600. على Windows يقع في `%LOCALAPPDATA%` الخاص بالمستخدم.
* النسخ الاحتياطي: scrypt (N=2^15) لاشتقاق المفتاح + AES-256-GCM مقطعاً مع ربط رقم المقطع وعلم "الأخير" في البيانات المصاحبة ⇒ أي عبث أو حذف مقاطع أو اقتطاع يُكتشف.
* الاستعادة تتحقق من سلامة قاعدة البيانات وتمنع Zip-Slip قبل استبدال أي شيء.
* الإيقاف الفوري يوقف كل الجلسات ويلغي إذن قراءة الشاشة والتحليل المستمر.
* حذف كل البيانات يتطلب كتابة عبارة التأكيد حرفياً.
* لا تُحفظ أي كلمات مرور لمنصات التداول — لا يوجد حقل لها أصلاً.
* تشفير قاعدة البيانات نفسها (SQLCipher) خيار مخطط له؛ حالياً الحماية بصلاحيات نظام الملفات وتشفير النسخ.

## 4. مسار الإشارة المستقبلي (المرحلة 8)
تحقق البيانات → الاتجاه → قوة الحركة → الشموع السابقة → الشمعة الحالية (دون افتراض إغلاقها) → المؤشرات المفعّلة → الدعم/المقاومة → العرض/الطلب → استرجاع الاستراتيجيات المعتمدة → شروطها → العوامل المعارضة → جودة الفرصة → المدة → الأسباب → `BUY | SELL | WAIT`.
كل إشارة تُحفظ عبر `RecordsService.record_signal` الذي يفرض القواعد على مستوى الكود وقاعدة البيانات (CHECK constraints).
