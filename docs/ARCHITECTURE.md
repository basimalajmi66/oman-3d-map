# المخطط المعماري — Universal AI Trading Assistant

## 1. المبادئ الحاكمة
| المبدأ | كيف يُطبَّق |
|---|---|
| المستخدم صاحب القرار | لا توجد أي واجهة برمجية أو زر ينفذ صفقة. أزرار BUY/SELL تعرض التوصية وتفاصيلها فقط. `trading_mode` لا يقبل إلا `manual`. |
| محلي أولاً | كل البيانات في مجلد واحد على الجهاز (SQLite + مخزن ملفات). المحرك يستمع على `127.0.0.1` فقط. لا رفع سحابي. |
| لا معرفة دون موافقة | كل ما يُضاف يدخل بحالة `pending_review`. المحرك يبحث في `approved` فقط. تعديل محتوى عنصر معتمد يعيده للمراجعة. |
| الصدق قبل الشكل | حين لا يتوفر مكوّن، يقول النظام ذلك (`engine_available=false`, `unsupported_yet`) ويعرض WAIT بدل أي رقم مختلق. |
| لا قرار من مؤشر واحد | `min_confluence_factors ≥ 2` في الإعدادات، و`record_signal` يرفض BUY/SELL بعوامل أقل من الحد. |
| الثقة ليست احتمالاً | كل إشارة تحمل `confidence_calibrated`، ولا تكون 1 إلا بدليل معايرة خارج العينة. |

### لماذا محرك Python منفصل وواجهة Flutter؟
* **Python** هو المكان الطبيعي لـ OpenCV وOCR وFFmpeg وWhisper ونماذج ML المحلية وpandas للاختبار التاريخي.
* **Flutter** يعطي واجهة واحدة لـ Windows وAndroid وTablet وiOS.
* العقد بينهما (`EngineApi`) واجهة مجردة، فالواجهة لا تعرف هل المحرك عملية منفصلة أم مضمّن.

### تشغيل المحرك حسب النظام
| النظام | طريقة التشغيل | ملاحظات |
|---|---|---|
| Windows | `engine\uata-engine.exe` (PyInstaller) بجانب التطبيق، يشغّله `EngineLocator` تلقائياً | مُتحقق منه: الملف التنفيذي يُبنى ويعمل. |
| Android | Python مضمّن عبر **Chaquopy 17.2** يشغّل نفس الحزمة `uata`؛ `MainActivity.kt` يبدؤه عبر قناة `uata/engine` في `filesDir/uata` | المرحلة 2 (مكتوب، يُبنى في CI). النافذة العائمة عبر `flutter_overlay_window` بإذن `SYSTEM_ALERT_WINDOW`؛ استقبال المشاركة عبر `receive_sharing_intent`؛ HTTP غير المشفر مسموح لـ 127.0.0.1 فقط؛ `allowBackup=false`. الالتقاط المستمر بـ MediaProjection في المرحلة 3. |
| Tablet | نفس تطبيق Android بتخطيط متكيف (الشاشات العريضة تعرض قائمة + تفاصيل) | التخطيط المتكيف موجود منذ المرحلة 1. |
| iOS | تطبيق مرافق: تحليل صور/ملفات ومشاركة الشارت عبر Share Extension. المحرك إما مضمّن (Python-for-iOS) أو الاتصال بمحرك الكمبيوتر على الشبكة المحلية بعد اقتران صريح | iOS لا يسمح بنوافذ عائمة فوق التطبيقات ولا بالتقاط شاشة تطبيقات أخرى. |

## 3. الأمان
* المحرك يرتبط بـ `127.0.0.1` فقط.
* توكن عشوائي جديد في كل تشغيل يُكتب في `api_token` بصلاحيات المالك فقط (0600)، ولا تقبل أي نقطة نهاية (عدا `/health`) بدونه. يمنع ذلك صفحات المتصفح والبرامج الأخرى من التحكم بالمحرك (لا CORS).
* مجلد البيانات 0700، قاعدة البيانات 0600. على Windows يقع في `%LOCALAPPDATA%` الخاص بالمستخدم.
* النسخ الاحتياطي: scrypt (N=2^15) لاشتقاق المفتاح + AES-256-GCM مقطعاً مع ربط رقم المقطع وعلم "الأخير" في البيانات المصاحبة ⇒ أي عبث أو حذف مقاطع أو اقتطاع يُكتشف.
* الاستعادة تتحقق من سلامة قاعدة البيانات وتمنع Zip-Slip قبل استبدال أي شيء.
* الإيقاف الفوري يوقف كل الجلسات ويلغي إذن قراءة الشاشة والتحليل المستمر.
* حذف كل البيانات يتطلب كتابة عبارة التأكيد حرفياً.
* لا تُحفظ أي كلمات مرور لمنصات التداول — لا يوجد حقل لها أصلاً.
* تشفير قاعدة البيانات نفسها (SQLCipher) خيار مخطط له؛ حالياً الحماية بصلاحيات نظام الملفات وتشفير النسخ.

## 4. مسار الإشارة المستقبلي (المرحلة 8)
تحقق البيانات → الاتجاه → قوة الحركة → الشموع السابقة → الشمعة الحالية (دون افتراض إغلاقها) → المؤشرات المفعّلة → الدعم/المقاومة → العرض/الطلب → استرجاع الاستراتيجيات المعتمدة → شروطها → العوامل المعارضة → جودة الفرصة → المدة → الأسباب → `BUY | SELL | WAIT`.
كل إشارة تُحفظ عبر `RecordsService.record_signal` الذي يفرض القواعد على مستوى الكود وقاعدة البيانات (CHECK constraints).

## 5. قارئ الشارت (المرحلة 3)
```
صورة ─► assess_image (دقة، حدة، تباين) ─┐
      └► detect_candles:                 ├─► ChartReader ─► usable / abstain_reasons
           لون الخلفية → قناعا HSV (أخضر/أحمر)        data_quality (الأضعف يغلب)
           فتح عمودي يزيل خطوط المتوسطات              candles[] (بكسل + نسبي + أسعار إن قُرئت)
           مكونات متصلة + دمج المقطوع                 الشمعة الأخيرة = possibly_forming
           قياس الجسم والفتيل على القناع الأصلي        price_scale | null
           تجاوز فجوات ≤4px تحت الخطوط                 timeframe من العنوان
           استعادة الشموع الصغيرة في شبكة التباعد      missing_slots
           إسقاط ملصقات السعر
      └► axis (Tesseract): تسميات رقمية → انحدار خطي مع إسقاط القيم الشاذة؛
           يُقبل فقط إذا R² ≥ 0.9995 والميل سالب، وإلا: قيم نسبية فقط
```
* الدقة **مقيسة** على رسوم اصطناعية بقيم معروفة (`uata/vision/synthetic.py`) وتُفرض كحدود دنيا في `tests/test_vision.py`.
* المحرك لا يصدر أي إشارة من القراءة؛ يبقى WAIT مع `signal_engine_not_installed` أو `image_quality_insufficient`.

## 6. محرك التحليل الفني (المرحلة 4)
```
شموع مكتملة فقط (من القارئ بالأسعار أو بقيم نسبية، أو من مصدر بيانات عبر /analysis/technical)
   │
   ├─ indicators.py  SMA/EMA/RSI(Wilder)/MACD/Bollinger/ATR/ROC/انحدار — كل قيمة عند i تستخدم 0..i فقط
   ├─ patterns.py    مطرقة، رجل مشنوق، شهاب، مطرقة مقلوبة، دوجي، ماروبوزو، ابتلاع، نجمة الصباح/المساء، شمعة داخلية
   ├─ structure.py   قمم/قيعان مؤكدة (j+k ≤ i)، الاتجاه (انحدار/ATR + HH/HL)، دعم/مقاومة بالتجميع،
   │                 مناطق عرض/طلب (قاعدة هادئة + اندفاع ≥ 2 ATR)، تجمعات السيولة، قمة/قاع مزدوج، حركة مفاجئة
   └─ engine.py      15 عاملاً ↔ إعدادات المستخدم: اتجاه + قوة + رمز سبب؛ حالة السوق؛ ملخص التوافق
```
* كل العتبات نسبية إلى ATR أو نسب مئوية ⇒ النتائج متطابقة بالأسعار الحقيقية أو بالقيم النسبية من الصورة (مُختبر).
* لا يصدر المحرك BUY/SELL؛ يقدم العوامل المؤيدة والمعارضة لمحرك القرار في المرحلة 8.

## 7. المكتبة والاسترجاع المعزز (المرحلة 5)
```
ملف/ملاحظة ─► extract (PDF صفحات · DOCX فقرات/جداول · XLSX ورقة+صفوف · صورة OCR · نص)
            ─► _ingest: عناصر بموقعها + قواعد مقترحة (شرط + فعل) + فهرسة (FTS5 + متجه)
            ─► learning_report: ملخص، مفاهيم، قواعد، تعارضات مع القواعد المعتمدة ─► بانتظار موافقتك
تحليل شارت ─► عوامل فنية ─► استعلام مفاهيم (عربي/إنجليزي) ─► Retriever (BM25 + متجه، دمج RRF، المعتمد فقط)
            ─► "معرفة ذات صلة" مع المصدر والموقع
```
* معجم مفاهيم تداول ثنائي اللغة يربط "مؤشر القوة النسبية" بـ RSI و"ابتلاع" بـ engulfing… فيُعثر على ملاحظة عربية باستعلام إنجليزي والعكس.
* لا نموذج لغوي ولا اتصال خارجي: الاستخراج والقواعد والبحث محلية وحتمية.

## 8. تحليل الفيديو التعليمي (المرحلة 6)
```
فيديو ─► عامل واحد في الخلفية (طابور؛ لا تحليلان متزامنان) ─► تقدم %
   نص منطوق: ملف ترجمة SRT/VTT (توقيت دقيق) │ أو نموذج faster-whisper محلي إن وُجد │ أو "غير متوفر" مع السبب
   إطارات كل 1ث ─► تغير المشهد (هيستوجرام ألوان + تغير المحتوى للشرائح النصية) أو كل 10ث
        ├─ قارئ الشارت: شارت صالح؟ ─► تحليل فني ─► "مثال" مرتبط بالوقت
        └─ وإلا OCR عربي+إنجليزي مع الثقة ─► نص شاشة بنطاق زمني (دمج المتشابه)
   ─► قواعد (دخول/امتناع/خروج) بالوقت والوضوح ─► ملخص استخراجي ─► استراتيجية "مسودة" في جدول strategies
   ─► عناصر معرفة (video_timestamp_ms، clarity) + فهرسة + تقرير تعلم بانتظار الموافقة
```
* إعادة التحليل تستبدل غير المعتمد فقط؛ المعرفة المعتمدة تبقى.
* الاستراتيجية تبقى `draft` حتى بعد اعتماد المعرفة — لا تُعتمد قبل اختبارها (المرحلة 7) وموافقتك.

## 9. الاستراتيجيات والاختبار التاريخي (المرحلة 7)
```
قواعد معتمدة (المرحلتان 5–6) ─► translate (مفاهيم ← شروط؛ غير القابل للاختبار يُعرض كما هو)
بطاقة استراتيجية (إصدار) = {long:{all}, short:{all}, veto, duration_sec}
CSV حقيقي │ بيانات اصطناعية (موسومة) ─► FeatureSet (مؤشرات سببية + قمم مؤكدة j+k≤i + أنماط + حالة السوق)
run_backtest: إشارة على الشمعة المغلقة i ─► دخول عند افتتاح i+1 ─► انتهاء عند إغلاق i+مدة
              صفقة واحدة في كل مرة · عائد ثابت (payout) · داخل/خارج العينة بالزمن · حسب حالة السوق
gate: بيانات حقيقية + ≥30 صفقة خارج العينة + عائد متوقع موجب + معامل ربح > 1  ─► ثم موافقتك
suitable(حالة السوق) ─► الاستراتيجيات المعتمدة مرتبة بعائدها خارج العينة في تلك الحالة (للمرحلة 8)
```
* تعديل تعريف الاستراتيجية = إصدار جديد ⇒ تعود مسودة، والاختبارات القديمة لا تُحتسب.
* النتائج تُخزن لكل (استراتيجية، إصدار، بيانات) ولا تُخلط أبداً.

## 10. محرك القرار (المرحلة 8)
```
قراءة الشارت + التحليل الفني + المعرفة المعتمدة + الاستراتيجيات المعتمدة
 1 صحة البيانات (قابلة للقراءة، الجودة ≥ حدك، الإطار الظاهر = إعدادك)
 2 الاتجاه · 3 القوة · 4 الشموع السابقة · 5 الشمعة المتكونة (لا يُفترض إغلاقها؛ الحركة القوية المعاكسة = عامل معارض)
 6 المؤشرات · 7 الدعم/المقاومة · 8 العرض/الطلب
 9 استراتيجيات معتمدة اجتازت البوابة ومختبرة على نفس الإطار الزمني
10 شروطها على آخر شمعة مكتملة (FeatureSet سببي) · تعارض الاستراتيجيات ⇒ WAIT
11 العوامل المؤيدة ≥ حدك والمعارضة أضعف
12 تقدير جودة الفرصة (غير معاير) ≥ حدك
13 المدة = المدة المختبرة ضمن نطاقك
14 الأسباب  ⇒  BUY | SELL   — أي إخفاق ⇒ WAIT مع رمز السبب
```
* التسجيل: كل تحليل سوق جديد (شمعة مكتملة جديدة) يُسجَّل، بما فيه WAIT؛ الصورة غير المقروءة لا تُسجَّل؛ تهدئة بعد BUY/SELL.
* الثقة تبقى `confidence_calibrated = false`، ويُعرض بجانبها دليل الاستراتيجية الفعلي خارج العينة (عدد الصفقات، نسبة النجاح وفترة الثقة، العائد المتوقع).

## 11. الإحصائيات والنتائج (المرحلة 9)
* `POST /signals/{id}/result`: النتيجة تُسجل من الإشارة نفسها؛ الاستراتيجية والوقت والمدة والإطار وحالة السوق والثقة والجودة تُنسخ آلياً (نتيجة واحدة لكل إشارة؛ WAIT بلا نتيجة).
* `StatsService.dashboard(account)`: نوع حساب واحد في كل مرة؛ كل نسبة مع حجم العينة وفترة Wilson؛ المجموعات دون 10 نتائج "عينة غير كافية".
* `insights(account)`: فروق خارج فترة ثقة المجموعة فقط؛ اتساق الثقة التقديرية مع النتائج (دليل المعايرة)؛ سلاسل الخسائر وتركزها؛ **مراجعة استراتيجية** فقط بعد 30 نتيجة وإذا كان الحد الأعلى لفترة الأداء الفعلي أقل من الحد الأدنى لفترة الاختبار خارج العينة — اقتراح لا يغير شيئاً.
